# 常用 Git 操作与待补功能

## 0.2.20 新增

| 场景 | 应用入口 | 行为 |
| --- | --- | --- |
| 不要某个文件的编辑 | 变更文件右键 → 丢弃文件修改 | 恢复到 HEAD，同时丢弃对应的已暂存、未暂存修改；新增已暂存文件会删除 |
| 不要某个目录的改动 | 文件夹右键 → 丢弃目录中的修改 | 预览该目录内所有受影响文件，不受搜索过滤影响 |
| 全部回到最近一次提交 | 变更文件列表的“丢弃全部未提交修改”按钮 | 默认保留未跟踪新文件；可明确勾选删除这些新文件，忽略文件不清理 |
| 回退到某次提交 | 历史 → 选择提交 → 重置到此提交 | 选择 soft、mixed、hard，并预览相关文件与离开当前分支历史的提交数 |

“取消暂存”只改变下次提交选择，不恢复文件内容。“丢弃修改”恢复文件内容，但不会回退提交历史。

- **Soft**：移动当前分支指向，保留工作区和暂存区；适合重新整理最近几次提交。
- **Mixed（默认）**：移动当前分支指向，保留磁盘文件，将暂存区恢复为目标提交；适合撤销提交后重新选择内容。
- **Hard**：移动当前分支指向，将已跟踪文件及暂存区恢复为目标提交；未提交内容会丢失。

这几种 reset 都只影响本地，不自动改动远程分支。已经分享给其他人的提交通常应使用 revert 生成反向提交；本次没有新增强制推送入口。

破坏性操作需要查看文件清单并确认。预览之后如文件、HEAD 或暂存区发生变化，原确认会被拒绝，必须重新预览。Hard reset 遇到会被覆盖的未跟踪/忽略文件时会阻止操作，不会默默删除。当前不处理含 submodule 或未解决冲突的仓库；进行中的合并、rebase、cherry-pick 也需要先单独完成或中止。

## 下一批建议

以下为基于当前代码检查的功能缺口，并非已经实现。

| 优先级 | 功能 | 最常见的使用场景 | 建议入口和默认行为 |
| --- | --- | --- | --- |
| P1 | Stash 临时保存、恢复、删除 | 改到一半要切分支、拉代码或处理紧急任务 | 变更页“暂存到 Stash”；默认包含已跟踪修改，新文件单独选择；恢复与删除分开 |
| P1 | 撤销上次提交并保留修改 | 刚提交就发现内容选错 | 提交区“撤销上次提交”，使用 mixed reset；明确显示已推送状态 |
| P1 | Amend 修改最近一次提交 | 漏了文件或提交说明有错 | 提交区可选“修改上次提交”；已推送提交额外说明会改写历史 |
| P1 | Revert 撤销某次提交 | 已经推送的错误提交需要撤回 | 历史右键“撤销此提交”，生成新的反向提交；merge commit 另行处理 |
| P1 | 冲突文件列表及继续/中止操作 | Pull、merge、stash 恢复后出现冲突 | 显示冲突文件，打开外部合并工具，提供标记解决及继续/中止 |
| P2 | 按代码块/选中行暂存、丢弃 | 同一个文件里包含两件不同的改动 | Diff 代码块操作；丢弃仍需确认，只影响选中代码块 |
| P2 | 分支删除、重命名、合并 | 开发完成后清理分支或整合功能 | 分支树右键；默认阻止删除未合并分支，明确区分本地与远程分支 |
| P2 | 远程仓库管理 | 更换 origin、添加 upstream、修改 URL | 仓库设置中的 remote 列表；修改后重新确认账号绑定 |
| P2 | 提交搜索、分支比较、文件历史/Blame | 找某次修改或查看一行代码是谁改的 | 历史搜索框、文件右键历史；比较视图显示分支间提交和差异 |
| P3 | Cherry-pick、Tag、交互式 Rebase | 迁移修复、标记版本、整理提交历史 | 放在历史与分支的高级菜单，明确冲突恢复与历史改写影响 |

建议顺序：先做 Stash、撤销上次提交、Amend 和 Revert，再完善冲突处理与代码块操作。
